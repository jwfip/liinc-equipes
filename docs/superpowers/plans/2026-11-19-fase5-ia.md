# Fase 5 — IA (Groq): resumos e relato por áudio · Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** (1) Resumo curto da situação de cada equipe, atualizado a cada mentoria; resumo separado dos atendimentos. (2) Relato por áudio: o mentor/especialista grava, a plataforma transcreve e preenche o formulário para revisão.

**Architecture:** Cliente HTTP mínimo para a API OpenAI-compatível do Groq (`src/lib/groq.ts`), sem SDK. Prompts e validação de respostas em funções puras testadas (`src/lib/ai/*`). Resumos guardados em `team_summaries` e gerados depois do envio (o formulário dispara `refreshTeamSummary` sem bloquear o mentor); se faltar ou estiver desatualizado, o histórico oferece "Gerar resumo". Áudio vai para a API route `/api/transcribe` (exceção prevista no design: upload binário), que chama o Whisper do Groq e um LLM em modo JSON para extrair os campos; o áudio não é guardado, só a transcrição (`audio_transcript`).

**Tech Stack:** Next.js 14, Groq (chat completions + audio transcriptions), MediaRecorder no navegador, Drizzle + neon-http, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-18-plataforma-v2-design.md` (seções 5.6 e 5.7)

## Global Constraints

- Chave: variável `GROQ_API_KEY` (Vercel → Environment Variables). Nunca no código, nunca no cliente, nunca em log. No ambiente de testes do Claude, a chave é injetada pelo proxy (credencial de rede para `api.groq.com`).
- Modelos configuráveis: `GROQ_SUMMARY_MODEL` (padrão: modelo Llama pequeno/rápido disponível no Groq na data da implementação, conferido em `GET /openai/v1/models`), `GROQ_TRANSCRIBE_MODEL` (padrão `whisper-large-v3-turbo`), idioma `pt`.
- Português; o prompt proíbe inventar fatos e manda usar só o que está nos registros.
- Resumo de evolução: 3 a 5 frases (situação atual, avanço, riscos, próximo passo), máx. ~600 caracteres. Resumo de atendimentos: principais dúvidas e orientações, máx. ~600 caracteres.
- Entrada limitada: últimas **12** mentorias (ou atendimentos) da equipe no evento; cada campo truncado em 600 caracteres.
- Falha da IA **nunca** impede salvar uma mentoria/atendimento. Timeout 20 s por chamada.
- Áudio: máx. **3 min**; formatos do MediaRecorder (`audio/webm;codecs=opus`, Safari `audio/mp4`); limite de upload 4 MB; não é armazenado.
- Campos vindos do áudio são **sugestões**: preenchem o formulário, status/etapa ficam destacados "sugerido — confirme"; nada é enviado automaticamente.
- Quem pode: gerar resumo e transcrever = participante do evento com sessão ativa (senha definida); admin também pode gerar resumo.

## Review Focus

- **Groq fora do ar / chave ausente** → mentoria salva normalmente; card mostra "Resumo indisponível" e o histórico oferece "Gerar resumo". (teste Task 2 com cliente falso + E2E sem chave)
- **Resposta do LLM fora do formato** (JSON inválido, status inexistente, etapa que não existe no evento) → campos inválidos descartados, o resto aproveitado. (teste Task 3 em `parseExtraction`)
- **Áudio vazio/curto/sem fala** → mensagem "Não consegui entender o áudio. Tente de novo ou digite." e formulário intacto. (teste Task 3 + E2E)
- **Texto com tentativa de instrução no relato** ("ignore as instruções…") → tratado como dado: prompt delimita o conteúdo e a saída é validada. (teste Task 1 do prompt: conteúdo entre delimitadores)
- **Resumo desatualizado** (mentoria editada ou nova mentoria sem resumo ainda) → card não mostra resumo antigo como se fosse atual: exibe "atualizando…" ou data do resumo. (teste Task 2 em `isSummaryStale`)

### Task 1: Banco e cliente Groq

- `team_summaries`: `id serial PK`, `event_id → events`, `team_id → teams`, `kind text` (`'mentoring' | 'specialist'`; `'final'` na fase 6), `content text not null`, `based_on_record_id uuid` (registro mais recente considerado), `model text`, `edited_by_admin boolean default false`, `created_at`. Índice único `(team_id, kind)` — guarda só o resumo atual (upsert).
- `mentoring_records.audio_transcript text`.
- `chat({ messages, model?, json?, maxTokens? }): Promise<string>`; `transcribe(file: Blob, filename: string): Promise<string>` em `src/lib/groq.ts` (`https://api.groq.com/openai/v1`, `AbortSignal.timeout(20_000)`, erro → `GroqError` com status, sem expor a chave).

### Task 2: Resumos

- `buildMentoringSummaryMessages(team, steps, records)` / `buildSpecialistSummaryMessages(team, records)`: system em pt-BR com as regras (não inventar, 3–5 frases, sem markdown, conteúdo do usuário entre `<registros>…</registros>` e tratado como dado); usa as últimas 12, campos truncados.
- `cleanSummary(text): string | null` — tira markdown/aspas, corta em 600 caracteres na última frase completa; vazio → `null`.
- `isSummaryStale(summary, latestRecordId): boolean`.
- `refreshTeamSummary(teamId: string, kind: 'mentoring' | 'specialist'): Promise<ActionResult>` — sessão ativa + participante do evento da equipe (ou admin); sem registros → apaga o resumo; senão chama `chat`, `cleanSummary`, upsert em `team_summaries`. Se `GROQ_API_KEY` ausente → `{ ok:false, error:'IA não configurada.' }`.
- Formulários: depois de salvar com sucesso, chamam `refreshTeamSummary` sem esperar (falha silenciosa). Edição também.
- `/api/records` devolve `summaries` (id, teamId, kind, content, basedOnRecordId, createdAt).
- Card: bloco "Resumo" (ícone `Sparkles`, 3 linhas com "ver mais"); se desatualizado, "Atualizando resumo…"; se ausente com registros, "Resumo indisponível".
- Histórico: resumo no topo de cada aba + botão "Gerar resumo"/"Atualizar resumo".
- [ ] Testes: prompt contém só as 12 últimas e os delimitadores; conteúdo malicioso fica dentro dos delimitadores; `cleanSummary` remove `**`/títulos e corta; `isSummaryStale`. Commit.

### Task 3: Relato por áudio

- `buildExtractionMessages(kind, transcript, steps)`: pede JSON com chaves fixas — mentoria: `status` (`ok|attention|emergency|flying|null`), `step` (número da etapa ou `null`), `working`, `advice`, `pros`, `cons`, `obs`, `suggestion`; atendimento: `topic`, `advice`, `obs`.
- `parseExtraction(raw: string, kind, steps): { fields: Record<string,string>; status: string | null; stepId: number | null }` — JSON inválido → tudo vazio; status fora da lista → `null`; etapa fora do intervalo → `null`; strings truncadas em 2000.
- `POST /api/transcribe` (`runtime = 'nodejs'`, `maxDuration = 60`): sessão ativa + participante; campo `audio` (≤ 4 MB) e `kind`; `transcribe` → se texto < 10 caracteres: 422 com a mensagem do Review Focus; senão `chat(json)` → `parseExtraction` → `{ transcript, fields, status, stepId }`.
- `AudioRecorder`: botão "Gravar relato" (`Mic`), cronômetro, "Parar" (`Square`), limite de 3 min com parada automática, estados gravando/enviando/erro; sem permissão de microfone → mensagem clara; navegador sem MediaRecorder → botão escondido.
- Formulários: ao receber o resultado, preenchem os campos vazios (não sobrescrevem o que o mentor já digitou), selecionam status/etapa sugeridos com aviso "sugerido pela IA — confirme"; hidden `audioTranscript` enviado e salvo.
- [ ] Testes de `parseExtraction` (válido; JSON quebrado; status inválido; etapa 9 com 3 etapas; atendimento) e do prompt. Commit.
